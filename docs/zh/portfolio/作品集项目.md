作品集项目路径

强 Agent 作品集应展示四个梯度：RAG 和 memory、tool orchestration、multi-agent coordination、abstraction。

## Track 1：个人知识库 Agent

展示 RAG + memory。

### Goal

构建一个本地 Agent：能搜索个人笔记、基于检索证据回答，并记住持久用户偏好，核心 Lab 不需要 API key。

### 最小范围

- 本地 document corpus。
- chunking 和 retrieval。
- 带 source references 的回答生成。
- user preference memory。
- missing evidence 时拒答。
- stale 或无关文档的 eval cases。

### 关键决策

- 如何区分检索事实与记忆事实。
- 如何引用来源。
- 如何处理冲突笔记。
- 如何防止记忆覆盖检索证据。

### 要包含的证据

- Eval 结果。
- 示例 traces。
- 失败案例。
- Prompt 与检索权衡。
- 简短生产 checklist。

### Stretch Goal

按 Mem0 或 Letta 风格加长期记忆，包含 privacy 说明和遗忘规则。

## Track 2：企业多工具 Agent

展示 tool orchestration 和 MCP-style boundaries。

### Goal

构建单 Agent：能在只读查询、写动作和人工升级之间路由。

### 最小范围

- tool allowlist。
- input/output validation。
- permission classification。
- destructive action confirmation。
- tool failure handling。
- observability logs。

### 关键决策

- 哪些工具只读、哪些可写。
- 哪些动作需要审批。
- 如何处理模糊工具结果。
- 工具失败与空结果的区别。

### 要包含的证据

- Tool schema table。
- success、rejection、failure 的 trace 示例。
- 成本与延迟记录。
- 高风险工具路径的回滚计划。

### Stretch Goal

通过 MCP-style 接口暴露 tool gateway，并包含 transport/auth 调试说明。

## Track 3：多 Agent 协作系统

展示 orchestration、consistency、error isolation。

### Goal

构建客服系统：router、retrieval、tool、verification、escalation Agent 各有明确职责。

### 最小范围

- router agent。
- retrieval agent。
- tool execution agent。
- verification agent。
- escalation path。
- shared trace model。
- error isolation 和 retry rules。

### 关键决策

- 哪些状态共享、哪些隔离。
- 谁能做最终面向用户的声明。
- verification 如何覆盖 subagent。
- 系统如何升级模糊或不安全案例。

### 要包含的证据

- Sequence diagram 或 Mermaid flow。
- Inter-agent message 示例。
- Regression evals。
- 带根因和修复的 incident story。

### Stretch Goal

加入 human-in-the-loop review queue，并解释审批边界。

## Track 4：自定义框架或模式

展示 abstraction、engineering depth、contribution readiness。

### Goal

设计可复用模式或迷你框架：稳定 input/output、安全检查、验证和测试。

### 最小范围

- pattern spec。
- deterministic Lab。
- unit tests。
- 带 expected outputs 的 tutorial。
- version anchors。
- failure mode 文档。
- maintenance notes。
- 起草前用 [Vibe Coding 工作流](../vibe-coding/README.md) 写一句提示规范（目标、接口、验收）。

### 关键决策

- 模式不该做什么。
- 执行前跑哪些安全检查。
- 验证如何成为强制步骤。
- 贡献者如何维护模式。

### 要包含的证据

- README 和 tutorial。
- 测试输出。
- 与框架特定实现的 before/after 对比。
- PR-ready 贡献说明。

### Stretch Goal

提交开源 PR、写一篇短文或做一次教这个模式的 talk。

## 作品集展示模板

每个项目写一页：

```markdown
# 项目名称

## Problem
你解决了什么用户或工程问题？

## Architecture
有哪些组件，为什么？

## Evaluation
哪些 evals 证明项目可用？

## Failure Modes
什么会坏，怎么处理？

## Production Readiness
有哪些 auth、safety、rollback、observability 控制？

## Trade-offs
为了更快，你接受了什么？

## Evidence
指向 traces、tests、docs 或 PRs 的链接。
```

## 质量线

作品集项目必须证明：

- 系统能运行。
- 系统能被测试。
- 系统能安全失败。
- 作者能解释 trade-off。
- 作者能在评审下改进项目。

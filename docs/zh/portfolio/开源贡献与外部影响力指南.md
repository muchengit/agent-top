# 开源贡献与外部影响力指南

开源影响力是证明 L5 Agent 能力的方式：定义可复用模式、改进工具，并产出别人可以检查的证据。

## 贡献类型

- **Pattern contribution**：提交稳定 Agent pattern 与测试或例子。
- **Lab contribution**：增加确定性练习来解释设计 trade-off。
- **Evaluation contribution**：改进 eval design、negative cases 或 release gates。
- **Observability contribution**：增加 trace contract、alert 例子或 debugging workflow。
- **Documentation contribution**：澄清概念、mapping、glossary 或 contributor paths。
- **Tooling contribution**：改进 CI、docs checks、templates 或本地校验。

## 好的贡献包

贡献应包含：

- Problem statement。
- 稳定 pattern 或 workflow。
- 最小可复现例子。
- Tests 或 validation commands。
- Failure modes。
- Maintainer notes。
- 双语文档。
- 关联 concepts 和 Labs。

## 提 PR 前检查

- 运行 repository checks。
- 确认 pattern 不只是 framework API wrapper。
- 把稳定概念和框架代码分开。
- 加入 negative examples 或 non-usage cases。
- 解释 pattern 失败时怎么办。

## 外部证据

可用的外部证据：

- 被接受的 PR。
- Maintainer 对 trade-off 的评论。
- Talk 或 workshop notes。
- 带例子的 pattern 文章。
- 被学习者使用的 Lab。
- 显示 adoption 或 follow-up use 的 issue thread。

## Impact 陈述模板

```markdown
# Contribution Impact

## Problem
这次贡献解决什么缺口？

## Pattern
引入什么可复用想法？

## Evidence
哪些测试、例子或 review 证明它有效？

## Adoption
下一批用户是谁？

## Follow-Up
还有什么没覆盖？
```

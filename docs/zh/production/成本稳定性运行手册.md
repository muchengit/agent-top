# 成本稳定性运行手册

成本稳定性运行把生产 Agent 的预算变成运行时规则。

## 运行模型

- 在流量增长前先定义预算。
- 在 Agent runtime 强制预算，而不只放在 dashboard。
- 在风险扩散前降级。
- 降级期间仍保留 trace。

## 成本预算

追踪：

- 每请求、每 tenant 的 token。
- 每个完成 task 的成本。
- 每个失败 task 的成本。
- 按 model、tool、retrieval source、workflow branch 统计 token。
- 按小时、天、tenant、feature flag 统计 budget burn rate。

预算公式：

```text
task_budget =
  prompt_tokens * prompt_cost +
  completion_tokens * completion_cost +
  retrieval_cost +
  tool_cost +
  storage_cost +
  eval_or_shadow_cost
```

## 延迟 SLO

为 planning、retrieval、model generation、tool calls、final verification 分别设预算。

告警条件：

- p95 latency 连续三个窗口超过预算。
- tool-call latency 超过 timeout policy。
- retry count 接近 retry budget。
- 单个 tenant 或 workflow 消耗份额异常。

## 降级模式

安全可保证时，优先降级而不是硬失败。

常见模式：

- 返回 concise sourced answer，而不是完整 reasoning chain。
- 禁用昂贵的 retrieval expansion。
- 跳过 optional verification 并记录缺口。
- 高风险 action 路由到人工审核。
- 冻结 memory writes，同时保留 audited reads。

降级不能绕过 auth、tool safety 或 audit logging。

## 网关证据

当 Agent 通过 model gateway、推理服务或本地 serving runtime 调用模型时，成本稳定性不只是“账单”，还包括路由决策。

每次模型调用应记录：

- `route`: gateway 选择的路由或策略。
- `provider_model`: 实际命中的 provider/model。
- `fallback_used`: 是否触发 fallback。
- `retry_count`: 重试次数。
- `budget_decision`: `continue` / `degrade` / `block`。
- `rate_limit_reason`: 被限流时的原因。
- `latency_ms`: 端到端和 serving runtime 延迟。
- `throughput_tokens_per_s`: gateway 或 runtime 可得到的吞吐证据。

这些字段应服务三个判断：为什么路由到该模型？为什么成本上升？是否可以安全 rollback 或 degrade？

## Serving Deployment Evidence

当 Agent 使用自托管 inference server 或外部 serving endpoint 时，部署也是稳定性证据。

每次部署或运行时变更应记录：

- `endpoint`: serving endpoint 或 gateway route。
- `model_revision`: model id、revision、commit 或 image tag。
- `revision_id`: 当前服务实际部署版本。
- `health`: health check 状态。
- `resource_limits`: CPU、GPU、memory、batch size 或 concurrency 限制。
- `timeout_policy`: request、stream、queue、retry timeout。
- `capacity`: 当前吞吐、排队长度或 saturation 状态。
- `rollback_action`: 可执行 rollback 或降级路径。

这些字段用于回答：为什么这次 serving 变更会影响 latency、cost、quality 或 safety？如何回滚？

## Guardrail 决策

运行时护栏应决策：

- `continue`：请求在预算内。
- `degrade`：请求有风险，但可以缩小范围完成。
- `block`：继续会突破硬安全或资源边界。

每个非 `continue` 决策都必须包含 reason code 和 request ID。

## 告警

最低告警：

- Token budget burn rate 超阈值。
- Cost per task 超阈值。
- p95 latency 超 SLO。
- Retry rate spike。
- Degradation rate spike。
- Tool-call timeout rate spike。
- 缺少 trace fields 的 degraded responses。

## Runbook

每个告警需要：

- Symptom。
- Immediate containment。
- Owner to page。
- Query 或 dashboard。
- Known safe rollback。
- 需要时用户沟通。
- Follow-up action type。

## 成本事故响应

1. 冻结 risky traffic paths。
2. 按 tenant、model、prompt version、workflow、tool 检查成本。
3. 禁用最高 burn 的 branch 或 prompt path。
4. 只在补 regression eval 或 budget test 后恢复。
5. 写 cost postmortem，包含 root cause 和 prevention action。

## 周复盘

复盘：

- Highest-cost workflows。
- Highest-failure workflows。
- Degradation reasons。
- 导致 regression 的 prompt versions。
- 消耗预算但没有提升 answer quality 的 tools。
- Missing budget telemetry。

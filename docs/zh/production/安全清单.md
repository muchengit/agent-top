Agent 安全清单

安全控制保护用户、数据和 Agent 的可预测运行。

## 必需控制

### Auth 和 Permissions

- 识别用户或租户。
- Retrieval 前检查授权。
- Tool execution 前检查授权。
- 不要只靠 prompt 做 access control。

### Tool Safety

- Tool allowlist。
- Read-only、write、destructive 分类。
- Destructive actions 要 approval。
- Tool arguments 校验。
- Tool call audit logs。

### Input Validation

- 拒绝 malformed inputs。
- 检测 obvious prompt injection。
- 限制输入大小。

### Output Validation

- Evidence required 时拒绝 unsupported claims。
- 阻断 sensitive data leakage。
- Missing critical evidence 时阻断最终回答。

### 记忆 Safety

- 记忆 按 user、tenant、purpose scoped。
- 不存 secrets/credentials。
- stale/conflicting memory 可见。
- 支持 deletion/forgetting。

### Rate 和 Cost Limits

- 按 user/tenant 限制请求速率。
- 限制每请求 tool-call count。
- 限制每任务 token spend。
- Stop escalation loops。

## 护栏证据

安全检查不应只写“通过”。每次 guardrail 决策都应记录可回放证据：

- `validator`: 规则或模型检查名。
- `verdict`: `pass` / `fail` / `repair` / `block`。
- `repair_attempt`: 是否尝试修复输出，修复预算是多少。
- `matched_policy`: 命中的策略名，不记录 secret。
- `fail_closed`: 不确定时是否 fail closed。
- `owner`: prompt、tool、retrieval、memory、runtime 或 release owner。

这些字段用于回答：为什么系统允许或阻止这个动作？如果不复现，如何证明同类问题已被拦截？

## MCP Tool Call Evidence

MCP 工具调用证据应能回答“谁、用什么工具、做了什么、谁批准、能否回滚”。

每次 tool call 至少记录：

- `server_id`: MCP server 或 tool gateway 标识。
- `tool_name`: 工具名，不含 secret。
- `input_schema_version`: 入参 schema 版本。
- `permission_scope`: read、write、destructive 或 admin。
- `transport_lifecycle`: initialized、calling、failed、cancelled、completed。
- `audit_actor`: 用户、租户、service account 或 human approver。
- `result_status`: success、empty、error、blocked、partial。

这些字段用于把工具失败、权限拒绝、空结果和部分成功分开处理。

## 风险分类

| Risk | Example | Control |
| --- | --- | --- |
| Low | read-only lookup | auth、trace、timeout |
| Medium | ticket comment、preference write | validation、rollback、audit |
| High | billing、permission、deletion | approval、idempotency、postmortem |
| Critical | data deletion、payment、credentials | human approval、full audit |

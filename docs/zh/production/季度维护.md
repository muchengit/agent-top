# 季度维护指南

季度维护让 Agent 内容保持新鲜，但不把文档变成维护负担。本文档是发现过期内容、重新验证 Lab、重新同步翻译、保持文档索引真实的运营契约。请在每季度开始时使用它，并在任何框架破坏性变更后使用它。

## 目的与适用范围

本指南适用于 `docs/en`、`docs/zh` 和 `labs/` 下的所有双语文档与可执行 Lab，覆盖：

- 校验所有 Markdown 文件的 `validated_date` 新鲜度。
- 在依赖、框架或 Python 版本变化后重新运行 Lab 测试。
- 检查英文与中文镜像的翻译同步状态。
- 管理破坏性变更与废弃（deprecation）流程。
- 向维护者汇报健康指标。

不在范围内：全新教程和面试题的内容撰写，这些遵循贡献工作流。

## 季度审查步骤

按下述顺序执行审查，使每一步的发现能输入下一步。

1. **刷新工作树。** 拉取最新 `main` 并确认分支干净：

   ```bash
   git pull --ff-only origin main
   git status --short
   ```

2. **检查每个 `validated_date`。** 仓库脚本会标记超过 180 天的文件：

   ```bash
   python scripts/check_repository.py
   ```

   此外，列出所有带日期锚点的文档，便于从最新开始审查：

   ```bash
   rg -l "validated_date:" docs | xargs -I{} sh -c 'echo "$(rg -o "validated_date: .*" "{}") {}"'
   ```

3. **检查 Lab 的 `tested_against` 锚点。** 每个锁定运行时或依赖版本的 Lab README 必须显式声明：

   ```bash
   rg -n "tested_against:" labs docs
   ```

4. **运行 repository checks。** 一次性校验必需路径、frontmatter、双语配对、链接和冲突标记：

   ```bash
   python scripts/check_repository.py
   ```

5. **运行 Lab tests。** 本地执行确定性测试套件，无需 API key：

   ```bash
   python -m unittest discover -s labs -p "test_*.py"
   ```

6. **扫描死链。** 相对链接由仓库脚本检查，但也要扫描 docs site：

   ```bash
   python scripts/check_repository.py
   rg -n "\]\(\.\.?/|\[.*\]\([a-z]" docs --glob "*.md" | head -50
   ```

7. **扫描 framework breaking changes。** 关注 `tested_against` 锚点中引用的框架与 SDK 上游 changelog（例如 LangChain、LangGraph、MCP SDK 发布）。变更落地后，遵循下面的 Breaking Change 流程。

8. **Review translation sync。** 确认 `docs/en` 中的每个 `i18n-key` 在 `docs/zh` 中都有完全一致的对应项：

   ```bash
   python - <<'PY'
   from pathlib import Path
   import re
   def keys(lang):
       out = set()
       for p in Path("docs", lang).rglob("*.md"):
           m = re.search(r"^i18n-key:\s*(.+)$", p.read_text(encoding="utf-8"), re.M)
           if m:
               out.add(m.group(1).strip())
       return out
   en, zh = keys("en"), keys("zh")
   print("missing in zh:", sorted(en - zh))
   print("extra in zh:", sorted(zh - en))
   print("pairs:", len(en & zh))
   PY
   ```

9. **Review deprecated content。** 列出所有 `deprecated` 标记，确认每项都有 owner、到期时间和替换链接：

   ```bash
   rg -n -i "deprecated" docs labs
   ```

10. **Check contributor workload。** 通过 open issue 和 PR 标签检查倦怠信号（例如某位维护者独自承担超过四分之三的 `maintainer-review` 或 `translation-needed` 事项），并在下一次规划会上重新平衡归属。

## 内容健康指标

在季度审查报告中跟踪这些指标，并与上一季度对比：

| 指标 | 定义 | 目标 | 获取方式 |
| --- | --- | --- | --- |
| 各等级完成率 | 通过自检或测试的 Docs/Lab 数量，按 L0-L5 | 已发布内容 100% | `python -m unittest discover -s labs` |
| 翻译同步率 | `last-synced` 在 14 天内的镜像文档比例 | ≥ 95% | `rg "last-synced" docs/zh` |
| 死链率 | 断链相对链接 / 相对链接总数 | < 1% | `check_repository.py` 输出 |
| 过期 Lab 率 | `validated_date` 超过 180 天的 Lab | 0 | `check_repository.py` 中的 `check_version_anchors` |
| 贡献者倦怠信号 | 超过 30 天的 open PR、无人认领的 `maintainer-review`、反复更换 reviewer | 0 项未解决 | GitHub labels + issue 搜索 |
| 读者反馈 NPS | 教程页面的调查反馈 | ≥ 30 | docs-site 反馈表单 |

## Breaking Change 流程

框架或 SDK 行为变化时，按此顺序执行，让每个锚点都保持真实：

1. **添加 `breaking-change` 标签** 到受影响的文档和 Lab issue。
2. **检查 Lab 是否仍运行。** 重新运行套件：

   ```bash
   python -m unittest labs.l4.regression_gate.test_lab
   ```

3. **更新 `validated_date` 和 `tested_against`** 为已验证的运行时和日期：

   ```yaml
   validated_date: 2026-09-17
   tested_against: langchain 0.3.x, openai 1.x, python 3.12
   ```

4. **一个季度内未更新**，则将内容标记为 `deprecated`，并附替换指针。
5. **添加 replacement link**，当内容被重写时，确保读者不会落到死胡同。

## 归档政策

- 废弃内容在替换发布后保留一个季度。
- 用指针替换旧页面到新教程；即使框架示例变化，也要保留稳定概念。
- 只有替换经维护者审查后才归档。
- 归档时将文件移动到 `docs/en/archive/` 或 `docs/zh/archive/`，并从索引中移除；未经记录决策不得删除。

## 角色与责任

| 角色 | 季度职责 |
| --- | --- |
| Docs 维护者 | 负责季度审查报告、最终归档决策、破坏性变更分诊。 |
| Lab owner | 重新运行 Lab 测试、更新 `tested_against`、修复失败的 Lab。 |
| 翻译负责人 | 确认 `i18n-key` 配对、更新 `last-synced`、解决翻译漂移。 |
| 社区负责人 | 跟踪贡献者工作量与倦怠信号。 |
| Reviewer | 验证健康指标表并批准报告。 |

## 常见失败与处理

| 失败 | 症状 | 处理 |
| --- | --- | --- |
| `validated_date` 过期 | `check_repository.py` 以 `is stale` 退出 | 重新验证内容或废弃；未经复核事实不得仅更新日期。 |
| Lab 测试回归 | 依赖升级后 `unittest` 报失败 | 在 `tested_against` 中固定新版本，修复 Lab，重跑套件。 |
| 翻译漂移 | `en` 与 `zh` 的 `i18n-key` 集合不一致 | 更新缺失的镜像，并在两侧同时更新 `last-synced`。 |
| 相对链接断裂 | 链接检查列出缺失目标 | 修复路径或移除链接；若文件被移动则补齐目标文件。 |
| 框架破坏性变更 | `tested_against` 锚点与现状不符 | 遵循 Breaking Change 流程，然后重跑 Lab 测试。 |

# 常见踩坑

## 踩坑 1：模糊提示

症状："改好一点"式提示，diff 每轮都在膨胀。

修复：先写规范。目标说不清就调研，不要提示。

## 踩坑 2：跳过 diff 审查

症状：助手"顺手修了"无关文件、改了权限或加了依赖。

修复：在跑任何东西之前审查完整 diff，回退范围蔓延。

## 踩坑 3：相信"应该能跑"

症状：没有运行、没有测试，"看起来正确"。

修复：搜索验收命令；找不到就是未验证。

## 踩坑 4：无证据地循环

症状：迭代很多轮，却不记录失败原因和最终检查输出。

修复：保存错误输出和最终绿灯输出；下次提示粘贴真实错误。

## 踩坑 5：过拟合单一输入

症状：修复通过了那一个失败用例，却破坏了其他一切。

修复：绿灯后跑完整套件，并为该失败添加回归用例。

## 踩坑 6：忽略双语镜像

症状：EN 文档更新了，ZH 镜像过期，`last-synced` 没动。

修复：在 Agent-Top 中，两侧一起更新或标注 `sync-required`；仓库检查会拦截未配对 key。

## 自测

1. 你能用一句话说清目标和验收检查吗？
2. 跑任何东西之前，你审查过 diff 吗？
3. 变更里有没有验收命令，且它通过了吗？
4. 你保留或补充了证据（测试、trace、eval）吗？
5. 双语镜像同步了，或明确标注了吗？

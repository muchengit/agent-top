# 什么是 Vibe Coding？

## 定义

Vibe coding 是一种软件开发风格：开发者通过自然语言指令与 AI 助手协作，通过快速迭代推进——提示、读 diff、跑检查、打磨。模型负责大部分初稿；开发者负责目标、审查和验证。

## 它不是什么

- 不是"随便许愿然后上线"。
- 不是跳过测试、lint 或证据的借口。
- 不是替代对系统的理解。
- 不限于原型；当验收标准明确时，同样的循环可以扩展到生产变更。

## 核心循环

1. **明确规范**：用一两句话写清目标、输入、输出和验收检查。
2. **生成**：让助手产出初稿或具体补丁。
3. **审查**：像读陌生人写的代码一样读 diff，检查范围、假设和隐藏副作用。
4. **运行**：执行确定性检查（单元测试、编译、lint、smoke）。
5. **打磨**：针对失败用精准提示迭代，而不是模糊描述。
6. **记录**：保留证据——测试、trace、eval——让结果之后可审查。

## 为什么有效

- 去掉输入摩擦和样板代码，把精力留给设计与审查。
- 让内循环（写 → 跑 → 修）足够短，便于探索替代方案。
- 产出可审查的 diff，这正是资深工程师会要的产物。

## 为什么会失败

- 规范模糊时，循环退化成随机修改。
- 缺失验证时，"看起来合理"取代"已被证明"。
- 开发者不再读 diff 时，助手的自信错误就成了产品的 bug。

## 与 Agent-Top 的关系

Agent-Top 的 Labs 与 Examples 是确定性且可运行的。Vibe coding 是构建和扩展它们的工作流：验收标准（测试通过、链接有效、双语镜像同步）不会改变。

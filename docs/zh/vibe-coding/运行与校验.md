# 运行与校验

## 规则

一个 vibe-coded 变更只有在仓库的确定性检查全部通过后才算完成。在 Agent-Top 中即：

```bash
python3 scripts/check_repository.py
python3 -m unittest discover -s labs -p 'test_*.py'
python3 -m compileall -q labs scripts
python3 -m ruff check .
python3 scripts/smoke_examples.py
python3 scripts/smoke_multilingual_labs.py
```

## "已验证"的含义

- **可运行**：命令存在且退出码为 0。
- **确定性**：相同输入得到相同结果，不依赖网络或 API key。
- **有证据**：测试、trace 或 eval 记录行为，评审者可以重跑。
- **已镜像**：对 Agent-Top 文档，EN 是源，ZH 保持相同 `i18n-key` 并更新 `last-synced`。

## 反馈循环

1. 先跑最窄的检查（你改动文件的测试）。
2. 再跑模块级测试套件。
3. 开 PR 前跑仓库级门禁。

## 处理失败的检查

- 读第一个错误，而不是最后的摘要。
- 用精确的失败输入复现。
- 要求最小修复，别让助手重写无关代码。
- 重跑完整门禁，因为一个文件的修复可能破坏另一个。

## 给评审者的证据

vibe-coded 贡献应包含：

- 改了什么、为什么（一两句）。
- 验收命令及其输出。
- 任何对规范的刻意偏离。

这让 PR 无需信任助手也能被审查。

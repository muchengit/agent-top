# Agent 面试答案范例

这页用来准备 Agent 面试时可直接复用的回答结构。

## 通用回答结构

1. 重述问题和假设。
2. 列出约束：safety、cost、latency、privacy、trust。
3. 提出最小可行架构。
4. 说明核心 trade-off。
5. 识别 failure modes。
6. 加入 eval、trace、rollback、owner。
7. 说明第一步先构建什么。

## STAR：成本事故

**Situation**：客服 Agent 加入 optional research steps 后，cost per task 上升。

**Task**：我在负责降低成本，同时保持 answer quality 和 safety。

**Action**：
- 按 workflow branch 追踪 cost。
- 加 token budget 和 max research steps。
- 对低风险问题降级为 concise sourced answer。
- 加 cost 和 quality 的 regression evals。

**Result**：
- Cost per task 下降。
- Safety eval 仍为 green。
- Incident action 被纳入 release gate。

## STAR：RAG 质量

**Situation**：用户收到基于 stale documents 的回答。

**Task**：我负责 retrieval quality 和 answer grounding。

**Action**：
- 加 source freshness checks。
- 要求 factual answers 带 citations。
- 加 no-answer 和 stale-source evals。
- Trace 记录 retrieved source IDs。

**Result**：
- 减少 stale-answer cases。
- 缺少 evidence 时 refusal，而不是猜答案。
- 增加 source freshness 的 regression coverage。

## STAR：工具安全

**Situation**：Tool Agent 在意图不明确时也能执行 write actions。

**Task**：我负责防止 unsafe side effects。

**Action**：
- 将工具分为 read、write、destructive。
- 对 destructive actions 加 confirmation。
- 执行前校验 tool arguments。
- 记录 denied actions。

**Result**：
- 阻断 ambiguous destructive calls。
- 增加 denied actions 的 trace evidence。
- 降低 unsafe action incidents。

## STAR：生产发布

**Situation**：生产 Agent 只有 code revert，没有其他 rollback plan。

**Task**：我负责为 prompt、retrieval、tools、memory 定义 rollback。

**Action**：
- 增加 prompt version rollback。
- 禁用 risky tool paths。
- 必要时冻结 memory writes。
- 增加 rollback readiness release gate。

**Result**：
- Incident 不依赖 code-only rollback。
- Release gates 会阻断缺失 rollback plan。

## 追问准备

- 你最先监控什么？
- 哪个 eval 可以防复发？
- 如果 safety 失败怎么办？
- 流量增长十倍你会改什么？
- 哪些部分会保持 manual？

## 要避开的红旗

- 提工具但不说 ownership boundaries。
- 默认 memory 总是正确。
- 把 evals 当 optional。
- 不提 rollback 或 cost controls。
- 不说 failure modes。
- 只优化速度，不看 safety 或 evidence。

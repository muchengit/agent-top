# L0-L5 全题库

这是 Agent-Top 的 L0-L5 紧凑全题库。每个层级包含一道必问题，并沿用统一结构：题目、预期答案、面试官听什么、追问和红旗。

## 使用方法

- 30-45 分钟快筛：每层抽一道。
- 认真技术 review：抽三题，一道基础题、一道系统题、一道生产或模式题。
- 始终要求候选人解释 trade-off 和 failure mode，而不是只背定义。

## L0：基础概念

### 题目

prompt、system instruction 和 tool result 有什么区别？

### 预期答案

- prompt 是用户任务或请求。
- system instruction 设定角色、策略、输出格式、安全规则和升级行为。
- tool result 是工具返回的外部证据或状态，仍需要 validation。

### 面试官听什么

- 能区分 user input、system control、external evidence。
- 知道 tool result 可能 stale、incomplete、malformed 或 wrong。

### 追问

同一个 final answer 在 prompt 改了一个 token 后发生变化，第一步查什么？

### 红旗

- 把所有 model inputs 当成等价。
- 默认 tool output 可信。

## L1：Agent 组件

### 题目

解释一个最小 ReAct Agent，以及你会使用哪些 stop conditions。

### 预期答案

- Agent 在 planning/action/observation 之间循环。
- 应该在 success、max steps、repeated failure、ambiguous intent、policy violation 或 escalation 时停止。
- 每一步都要记录足够信息，方便后续 debug。

### 面试官听什么

- 能讲清楚 loop：state -> plan -> action -> observation -> next state。
- 知道无界 loop 会带来 cost、latency、safety risk。

### 追问

tool 返回 ambiguous result 时应该怎么办？

### 红旗

- 说不出为什么需要 step limit。
- 只把 ReAct 当 prompt template。

## L2：框架和 MCP

### 题目

如何为可靠单 Agent 设计 tool boundary 和 MCP-style failure handling？

### 预期答案

- Tool 应有一个清楚职责、typed inputs、validated outputs、explicit permissions、side-effect classification。
- MCP failures 应拆成 discovery、auth、schema、invocation、timeout、parsing。
- 破坏性或不可逆动作需要 confirmation、audit logs 或 rollback。

### 面试官听什么

- 按 risk classes 思考，而不是只按 API call 思考。
- 能给出具体 logs 和 trace fields。

### 追问

如何防止 Agent 基于 stale retrieved context 做 destructive write？

### 红旗

- 不管风险都要求人工确认。
- 分不清 permission failure 和 malformed output。

## L3：系统设计

### 题目

设计一个包含 RAG、memory、tools、human escalation 的客服 Agent。

### 预期答案

- 从 intent、permissions、trust boundaries 开始。
- RAG 用于 scoped policy/product knowledge，memory 用于 durable user context，tools 用于 order/ticket state，escalation 用于 unsafe 或 ambiguous actions。
- 定义 data ownership、citations、refusal behavior、evals、latency、cost。

### 面试官听什么

- 先拆 requirements，再讲架构。
- 能解释 retrieval、memory、tool state、human approval 如何交互。

### 追问

如何判断错误答案来自 retrieval、memory、model 还是 tool？

### 红旗

- 没有理由就上 multi-agent orchestration。
- 忘记 citations、refusal behavior 或 tenant boundaries。

## L4：生产化

### 题目

客户说 Agent 改错了账户。请讲你的 incident response。

### 预期答案

- 先 freeze 或 disable risky action path。
- 查 trace、prompt、retrieved context、tool arguments、authorization、final response。
- 定位 root cause：data、retrieval、model、tool schema、permission 或 prompt policy。
- 加 regression eval、rollback path、postmortem action，并明确 owner 和 due date。

### 面试官听什么

- 先做 safety 和 containment。
- 能把 incident response 接到 prevention controls。

### 追问

如果同样的问题可能再次发生，哪个 eval 应该 block 下次 release？

### 红旗

- 第一反应怪 model。
- 没有 rollback 或 regression prevention。

## L5：专家模式和影响力

### 题目

什么样的 reusable Agent pattern 值得贡献给 Agent-Top 或开源社区？

### 预期答案

- 解决跨项目重复问题。
- 有 stable inputs/outputs、explicit failure modes、safety checks、validation。
- 比 framework-specific code 更容易维护。
- 附带 Lab、docs、evals 或 traces，以及 migration/deprecation story。

### 面试官听什么

- 能区分 durable pattern 和 framework detail。
- 会讲 maintenance cost 和 contributor readiness。

### 追问

什么证据能让你判断 pattern 应该从 Lab 升级为 framework 或 standard？

### 红旗

- 贡献只是 framework wrapper。
- 没有 failure modes、docs、tests 或 migration story。

## 评分口径

- 0：模糊或背诵答案。
- 1：概念正确，但缺 production trade-off 或 failure path。
- 2：答案包含 system boundary、trade-off、measurement、rollback 或 prevention，并给出一个 concrete example。

通过建议：

- L0-L1 快筛：baseline 或 safety 题不得 0。
- L2-L4 技术面试：至少 80% 答案达到 2。
- L5 专家 review：pattern 题达到 2，且候选人提供 usage 之外的 evidence。

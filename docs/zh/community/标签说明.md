# GitHub 标签

标签帮助贡献者找到合适任务，也帮助维护者把 review 路由到正确的人，避免评审负载失衡。

## 标签指南

| 标签 | 含义 | 适用场景 | Review 路由 |
| --- | --- | --- | --- |
| `good first issue` | 适合新人的贡献 | 范围小的 docs fix、小 Lab 改进、术语清理 | Reviewer |
| `docs-only` | 仅文档改动 | 不改变 Lab 行为的 Markdown 编辑 | Reviewer；ZH 变更时加语言检查 |
| `translation-needed` | 可认领翻译任务 | EN source 已稳定，ZH mirror 待补 | Language reviewer；敏感内容加 owner |
| `sync-required` | 中英文不同步 | `last-synced` drift 或缺少 paired content | stale 或冲突时找 Maintainer |
| `deprecated` | 内容应指向替代页 | 过期示例或已被替代的指导 | Maintainer 审核替代路径 |
| `breaking-change` | 框架或 SDK 变化可能影响示例 | 版本锚点、Lab 行为、框架示例 | Maintainer |
| `maintainer-review` | 架构或安全审查 | 生产、安全、工具风险、多 Agent 拓扑 | Maintainer |
| `lab` | 可运行 Lab 内容 | Lab 代码、测试、README | Reviewer 并要求测试证据 |
| `interview` | 面试题或 rubric 内容 | 问题、答案要点、评分卡 | 内容 reviewer |
| `production` | 生产、安全、eval 或 postmortem 内容 | 发布门禁、事故、rollback、可观测 | Maintainer 或 production reviewer |
| `eval-evidence` | Agent 行为的 eval 结果或回归证据 | eval 集、评分、回归门禁 | Content reviewer |
| `original-pattern` | 新模式或框架贡献 | L5 模式目录、案例研究 | Maintainer |
| `good-first-L5` | 适合新人的 L5 路径任务 | 原创模式支持任务 | Reviewer |
| `external-impact` | 外部影响力证据 | PR、论文、演讲、案例、工具 | Maintainer |
| `safety-review` | 需要审查的安全关键变更 | 护栏、工具风险、拒绝行为 | Maintainer 或安全 reviewer |
| `release-governance` | 发布门禁或治理变更 | 发布门禁、回滚策略 | Maintainer |
| `sig-candidate` | 兴趣小组候选主题 | 社区话题分组 | Community lead |

## 使用规则

- 每个 issue/PR 使用一个主主题标签，再加路由标签。
- 只有任务能独立完成和评审时，才标记 `good first issue`。
- 只有 EN source 足够稳定时，才标记 `translation-needed`。
- EN 和 ZH 在 source 更新后发生 drift 时，标记 `sync-required`。
- 架构、安全、生产或 breaking changes 必须使用 `maintainer-review`。
- 不要用 `deprecated`，除非提供 replacement link 或 next-step guidance。

## 标签卫生

- 不要为了吸引注意随意堆叠标签。
- 关闭 issue 或 PR 前移除过期标签。
- PR 涉及多个区域时，在描述中说明主要 review route。
- 如果 EN source 不稳定导致翻译阻塞，先 comment blocker 再认领。

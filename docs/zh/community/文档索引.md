## 角色路径

| 角色 | 适合的首个任务 | Review 预期 |
| --- | --- | --- |
| Contributor | docs-only、translation-needed、小 Lab 改进 | 一个 reviewer + 中文语言检查 |
| Reviewer | 普通 Lab/文档 review、术语检查 | 不评审自己同月提交 |
| Maintainer | 架构、安全、生产、发布敏感变更 | 保持 stable pattern 与框架代码分离 |
| Core | roadmap、治理、贡献者激励 | 关注可持续性和 review 负载 |

## Good first issue 规则

Good first issue 应该：

- 只涉及一个文件或一个小 Lab。
- 可用 `python scripts/check_repository.py` 或 Lab 测试验证。
- 写清期望输出和 acceptance criteria。
- 使用正确标签：`good first issue`、`docs-only`、`translation-needed`、`sync-required`。

## 提交前

- 修改示例时更新 `validated_date`。
- 修改 Lab 时保留 `tested_against`。
- 框架特定代码放在 Lab，不放进概念文档。
- `docs/en` 和 `docs/zh` 下文档保留双语 metadata。
- 运行：`python scripts/check_repository.py`。

## 社区规范

- 默认使用 Markdown + 可执行 Lab。
- 英文为主源，中文镜像用 `i18n-key` 和 `last-synced` 跟踪。
- Good first issue 必须范围小、可测、可审。
- 生产内容必须带版本锚点。
- Review 质量必须可持续。

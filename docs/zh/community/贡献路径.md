贡献路径

Agent-Top 有四类主要贡献路径。

## 1. 撰写

写新教程、概念页或 Lab。

好的写作贡献应包含：

- 清晰目标。
- 关联 Lab 或模板。
- 预期输出。
- Trade-off 解释。
- 通过 repository checks。

## 2. 翻译

翻译英文源内容到中文。

翻译贡献应：

- 使用相同 `i18n-key`。
- 更新 `last-synced`。
- 术语与 glossary 保持一致。
- review 后再关闭 `translation-needed`。

## 3. 审校

检查准确性、清晰度和可维护性。

## 4. 维护

维护框架地图、CI、模板和发布卫生。

## 5. L5 Expert Evidence

为 L5 贡献提交证据包：原创模式、架构 review、eval/trace/risk/release 证据、外部影响力 artifact、mentorship/review 证据。

Good L5 evidence contribution:

- 使用 [`../../../templates/L5专家证据模板.md`](../../../templates/L5专家证据模板.md) 打包 pattern、governance 和 influence 主张。
- 把 claim 拆成 reviewer 能检查的小 artifact：Lab、eval、trace、risk packet、design review 或 issue/PR thread。
- 包含 failure modes、non-goals、rejected alternatives 和 residual-risk note。
- 标明需要的 label：`good-first-L5`、`original-pattern`、`external-impact`、`eval-evidence`、`safety-review`、`release-governance` 或 `sig-candidate`。
- 包含一个 mentoring 或 review 信号，证明贡献者能提升其他 contributor 的质量。

## 非 Python Lab 维护

Python 仍是默认可运行 Lab 语言，但新增 Node.js、Rust、Go、TypeScript 示例时必须写清楚 ownership。

每个非 Python Lab maintainer 应：

- 保持共享 pattern contract 不变。
- 更新语言相关命令和 version anchors。
- 请求 review 前运行对应 smoke path。
- 记录 intentional parity differences。
- CI 失败时路由给 owning language lane，而不是丢给 docs reviewer。

验收证据：

- Node.js：可运行命令和预期 stdout。
- TypeScript：`npm ci` 加本地 TypeScript compile 或 smoke output。
- Rust：compile/test command 和 failure behavior。
- Go：module path、`go test`、clean-checkout command。
- Parity reviewer：mismatch table 加 accept/rework decision。

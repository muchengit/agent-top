# 行业对标与 L5 专家路径

Agent-Top 保留 L0-L5 作为主学习脊柱，但本页说明它如何对标公开的 AI、云架构、开源和治理框架。目标不是复制外部框架，而是让 Agent-Top 的 L5 专家路径足够具体，方便学习者、reviewer 和维护者判断。

## 调研来源

外部来源只作为学习信号，不作为 Agent-Top 的权威政策。

| 来源 | Agent-Top 吸收点 | 不复制什么 |
| --- | --- | --- |
| DeepLearning.AI short courses | 主题 + 难度标签、hands-on modules、Agentic AI / RAG / MCP / memory / orchestration 主题簇 | 课程营销或厂商 completion claim |
| Microsoft Azure AI Engineer 学习路径 | 从需求、设计、开发、部署、集成、维护、调优到监控的角色能力 | 认证考试措辞 |
| AWS Well-Architected ML / GenAI lens | 架构 review pillar、证据化设计决策、operational readiness | 云厂商部署 recipe |
| NIST AI RMF 1.0 | Govern / Map / Measure / Manage 风险包 | 把合规 checklist 当作学习目标 |
| DORA metrics | 交付健康指标：lead time、review latency、release cadence、recovery time、instability | 把原始指标当个人评分 |
| Open Source Guides | contributor funnel、清晰入口、mentorship、PR review、testing/tooling 贡献路径 | 社区 policy boilerplate |
| Apache / Python governance | 轻量治理、release owner、sign-off、maintainer path、inclusive contribution | 重流程和正式投票仪式 |
| CNCF / Kubernetes | SIG/workstream 所有权：evaluations、safety、observability、translations、releases、ambassadors | 完整基金会治理模型 |

## 业界如何拆分专家能力

多数公开框架不是单一 L0-L5 阶梯，而是混合不同维度：

| 维度 | 常见形态 | Agent-Top 映射 |
| --- | --- | --- |
| 学习难度 | Beginner / intermediate / advanced modules | L0-L3 教程和 Lab 进阶 |
| 职业角色 | AI engineer 从设计到监控的职责 | L2-L4 实践路径 |
| 生产架构 | pillar、风险控制、operational readiness | L4 生产指南和 L5 架构 review |
| 风险成熟度 | Govern / Map / Measure / Manage | L4 risk packet 和 L5 evidence bundle |
| 交付健康 | PR lead time、review latency、recovery time、instability | 社区和 release health metrics |
| 治理成熟度 | Reviewer、Maintainer、Core、release owner、SIG owner | L5 专家贡献和社区角色路径 |
| 外部影响力 | Talks、articles、workshops、accepted PRs、reusable artifacts | L5 impact evidence |

## L5 不只是“更多代码”

Agent-Top 现在把 L5 定义为 **pattern + governance + influence**：

- **Pattern quality**：能定义可复用输入、输出、failure modes、safety checks、verification、rollback 和 when not to use。
- **Governance quality**：能说明 ownership、escalation、release decisions、review gates、residual risk 和 maintenance burden。
- **Influence quality**：产出别人可 review 或复用的 artifact：accepted PR、maintainer-ready design doc、talk、workshop、article、Lab、checklist、template 或外部贡献。

这用可 review 的 evidence bundle 替代了模糊的“高级专家”标签。

## L5 专家证据包

请使用 [`../../../templates/L5专家证据模板.md`](../../../templates/L5专家证据模板.md) 打包 L5 主张。
准备 issue 或 PR 时，可参考 [`../community/L5专家候选任务.md`](../community/L5专家候选任务.md) 中的候选 L5 包。

L5 readiness 最低证据：

1. 一个原创 Agent pattern 或可复用 workflow。
2. 一个 deterministic Lab、executable example 或 reviewed case study。
3. 一个绑定该 pattern 的 eval、trace、release 或 risk packet。
4. 一份架构/设计 review，明确 non-goals 和 rejected alternatives。
5. 一个外部或可采用 artifact：accepted PR、issue thread、talk/workshop、article、template、checklist 或 maintained Lab。
6. 一个 mentoring 或 review 贡献，证明学习者能提升另一位 contributor 的质量标准。

起草任何原创 pattern 时遵循 [Vibe Coding 工作流](../vibe-coding/README.md)：提示前用一句话写明目标、接口与验收，并用 [`../../../labs/l5/vibe_coding_spec/README.md`](../../../labs/l5/vibe_coding_spec/README.md) 确认就绪。

## L5 Rubric

每个维度按 0-4 打分。强 L5 主张通常至少在 pattern quality、evidence 和一个 influence 维度达到 3 分。

| 维度 | 0 | 1 | 2 | 3 | 4 |
| --- | --- | --- | --- | --- | --- |
| Pattern quality | 一次性 prompt/script | 只有 idea | 稳定输入输出 | safety、verification、rollback、failure modes | 被另一个项目复用或 maintainer-ready |
| Architecture review | 没有边界 | informal notes | 清楚组件 | trade-offs、ownership、non-goals、rejected alternatives | 跨团队可复用 design 或标准 |
| Evidence | 无证明 | 只有 demo | Lab 或 test | eval/trace/risk/release packet | 带 regression 或 review trail 的维护证据 |
| Governance | 无 owner | 个人 notes | review checklist | release/maintainer gates | Maintainer/Core review path + backup owner |
| Influence | 私有工作 | 本地 write-up | 贡献草稿 | accepted PR 或 public article | talk、workshop、maintained Lab 或 adopted pattern |

## L5 专家角色

L5 readiness 可以解锁社区角色，但贡献数量本身不够。

| 角色 | Gate | Evidence |
| --- | --- | --- |
| Reviewer | 3 个 reviewable contributions + 5 次有用 review | good first review comments、docs/Lab review、无同模块自审违规 |
| Maintainer | 拥有模块且有 backup owner | module health、review quality、release/safety-sensitive review、至少 2 位 mentored contributors |
| Core | 参与 roadmap 和 release governance | cross-module decisions、governance notes、L5 evidence、冲突处理能力 |
| SIG owner | 拥有 workstream | charter、owner、backlog、meeting notes、monthly health update |
| Ambassador | 对外教学或分享 Agent-Top | talk、workshop、article、community Q&A、external PR、translated chapter 或 reusable example |

## 建议 L5 标签

标签要让专家路径可见，但不要制造压迫感。

| Label | 含义 |
| --- | --- |
| `good-first-L5` | 准备 L5 evidence bundle 的好起点 |
| `original-pattern` | 贡献提出可复用 Agent pattern |
| `external-impact` | 贡献包含 talk、PR、article、workshop 或 adoption evidence |
| `eval-evidence` | 贡献包含 eval、trace、risk 或 release evidence |
| `safety-review` | 贡献涉及 safety 或 permission-sensitive behavior |
| `release-governance` | 贡献影响 release、rollback 或 maintainer process |
| `sig-candidate` | workstream 已足够成熟，可考虑 SIG ownership |

## L5 工作的社区健康指标

L5 工作应按工程交付衡量，而不只是内容产出。

| 指标 | 为什么重要 | 目标 |
| --- | --- | --- |
| PR lead time | 说明专家贡献是否流动 | 记录 opened 到 merged 时间 |
| Review latency | 说明 maintainer bottleneck | 一周内有第一次 maintainer response |
| Release instability | 说明 docs、Labs 或 release gates 的变更风险 | release 时无已知 broken Lab path |
| Recovery time | 说明 blocker 修复速度 | 一个 release cycle 内修复或记录 blocker |
| Bilingual sync lag | 保护 EN/ZH 质量 | <= 14 天 |
| External adoption signal | 说明影响力是否溢出学习者本人 | public issue、talk、PR、workshop、article 或 reused artifact |

## 对 Agent-Top 学习的改变

- L0-L3 继续作为 implementation 和 system learning path。
- L4 应视为 production readiness：eval gates、risk packets、release checklists、rollback、postmortem。
- L5 应视为 reusable influence：patterns、governance、evidence、mentorship、external artifacts。

关键决策是：保持 L0-L5 主干，同时加入 rubric 和 evidence requirements。这样不会把 Agent-Top 硬套进某个公司内部阶梯，同时让 L5 可 review。

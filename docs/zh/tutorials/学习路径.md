# 学习路径

学习路径连接 Agent-Top 的教程、Lab、案例、速查表和作品集证据。想先完成一个具体任务，请先看 [`快速导航卡.md`](快速导航卡.md)。

## 目标读者与目的

- **主要读者**：想从第一次 LLM 调用一路走到 L5 专家证据的学习者，以及推荐下一步的导师。
- **目的**：把教程树整理成五条具体路径，每条都有明确的出口证据。
- **不适合**：一次性提问。请改用 [`教程参考地图.md`](教程参考地图.md) 或 [`快速导航卡.md`](快速导航卡.md)。

## 如何使用本文档

1. **评估你的证据**。检查你已经有哪些出口证据。
2. **选定一条路径**。完成它再开始下一条。
3. **先读后跑**。教程定义概念，Labs 证明它们。
4. **按路径存档证据**。每条路径保留一个文件，记录命令、输出和简短解释。
5. **反哺作品集**。每条路径至少产出一条 [`../portfolio/作品集项目.md`](../portfolio/作品集项目.md) 作品集条目。

## 如何选择路径

- **时间有限的学习者**：一周完成入门路径，然后进阶。
- **生产工程师**：系统路径之后走生产路径。
- **框架作者**：专家路径，然后用 L5 证据模板打包。
- **导师**：用出口证据把学习者放到下一条路径。

## 常见错误与规避

- **跳过出口证据**——证据是路径完整的标志。拿不出证据就不要开始下一条路径。
- **在路径之间跳来跳去**——路径是累积的。选定一条完成再换。
- **只读不跑**——Labs 的存在就是为了让论断可测试。每个都在本地跑一遍。
- **忽略安全 Labs**——guardrail 和安全材料提前出现是有原因的；跳过它，生产阶段还要重学。

## 可衡量指标

- **Completion**：当前路径的出口证据已存在。
- **Depth**：每个完成的 Lab 都有书面解释，不只是跑通。
- **Transfer**：不看 Lab 说明也能运行 [`../cases/文档索引.md`](../cases/文档索引.md) 中的相关案例。
- **Portfolio growth**：每条路径都向 [`../portfolio/作品集项目.md`](../portfolio/作品集项目.md) 贡献一个条目。

## 真实证据示例

```markdown
# Intermediate Path Evidence

## Tool Allowlist
- `read_file` — 允许，只读。
- `write_file` — 破坏性覆盖前需确认。
- `delete_file` — 默认拒绝；需要审批。
- `run_shell` — 仅按显式 allowlist 允许。

## Confirmation Rule
任何能销毁数据的工具都需要人工确认，包含确切目标路径和
建议的备份命令。

## Routing Decision
小型查询走低延迟模型；多步推理只有在任务需要规划时才
走更高成本模型。
```

## 路径之间

- **入门 → 进阶**：只有当你解释了 ReAct loop 和 stop conditions（而不是只跑通）时。
- **进阶 → 系统**：只有工具风险表存在且有一个有依据的路由决策时。
- **系统 → 生产**：只有 retrieval eval 和 refusal case 存在时。
- **生产 → 专家**：只有 release gate、postmortem 和 rollback plan 存在时。
- **专家 → 贡献**：用 L5 证据模板打包模式并开 PR。

## 导师笔记

- **先评估，不按级别指派**。问学习者已有哪些出口证据，再选下一条路径。
- **要求书面证据**。跑通一次 Lab 不够；要求学习者用自己的话写简短解释。
- **把作品集当作审计线索**。作品集索引应把每个项目链接回产生它的路径。
- **专家路径要配社区评审**。模式要等审查者能重跑，才算专家级。

## 常见停滞与排查

- **ReAct loop 不终止**——先回头复习 stop conditions 和 tool-result ambiguity，再添加更多工具。
- **Eval 分数不动**——检查 negative cases 是否真正到达 retrieval 步骤，而不是提前失败。
- **Postmortem 没有 owner**——没有 owner 和 due date 的 incident 不是完整证据。
- **模式被 review 拒绝**——最常见原因是缺少 failure-mode section；补上再提交。

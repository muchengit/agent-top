## 可吸纳模式

- **Tool schema-first**：先定义工具输入、输出、风险，再写 prompt。
- **Graph/stateful workflows**：复杂流程显式建模状态和跳转。
- **Role-based teams**：角色必须有职责边界和停止条件。
- **Structured output**：模型输出进入 schema validation。
- **RAG evaluation**：检索质量、答案相关性、证据忠实度分开评估。
- **Memory lifecycle**：抽取、去重、过期、删除都要有策略。
- **Observability contract**：每轮记录 prompt、tool、retrieval、guardrail、cost、latency。
- **Security red-team**：prompt、tool、MCP、agent workflow 都要有对抗测试。
- **Incident learning**：事故必须转成 eval、guardrail、trace 或 rollback action。
- **Prompt optimization loop**：版本化 prompt、生成候选、在 dataset 上评估、只上线可测得提升。
- **MCP policy proxy**：把权限、审计、mutation gates、PII redaction、rate limits 放到 tool execution 附近。
- **12-factor 运维纪律**：把环境、扩展、状态、日志和发布策略视为 Agent 架构问题。
- **Coding Agent workspace boundary**：把 repository context、command execution、file writes、tests、rollback state 分开。
- **Patch-first editing**：改代码时优先产出可 review 的 diff，而不是直接 mutation。
- **Test-driven Agent validation**：每个 code-changing step 都要找到最小验证命令。
- **Suggestion acceptance workflow**：区分 recommendation、approval、execution、post-check。
- **Source policy boundary**：把 crawling、parsing、storage、retrieval、citation 视为独立授权决策。
- **Ingestion metadata contract**：保留 source URL、crawl time、freshness、permission state、parser version、deletion state。
- **Browser action trace**：记录 visible context、action intent、screenshot 或 DOM summary、rollback state。
- **Eval dataset discipline**：dataset 版本化，每个 metric 都有清楚 pass/fail rule。
- **Structured output validation**：先定义 JSON schema、retry policy、invalid-output escalation 和 validation failures，再进入业务逻辑。
- **Sandboxed execution boundary**：把 shell、filesystem、network、credentials 当作独立执行权限。
- **Eval gate discipline**：prompt、tool 或 model 变更只有记录 dataset version、pass rate、regression diff、owner approval 后才能上线。
- **Error grouping evidence**：用 fingerprint、release SHA、route、owner、recurrence、severity 聚合运行故障，让复盘能看重复根因，而不是争论单条 trace。
- **Runtime hotspot evidence**：把 latency、CPU/memory、token cost、tool hotspot 绑定到 commit、release、model、prompt、tool、dataset version。
- **Deterministic lint gate**：在认为 style 或 safety issue 已解决前，记录快速 deterministic formatter/linter 的工具版本和精确 findings。
- **Tool and dependency lock evidence**：保存 Python、CLI、Agent、MCP 依赖的 lockfile/tool versions，让 release 能用同一工具链 replay。
- **Workflow provenance**：记录 workflow/activity id、input event id、retry attempt、dead-letter state、owner，让分布式 Agent workflow 可跨服务追踪。
- **GenAI telemetry vocabulary**：统一 span name、event name、model/provider attributes、token counts、cost units、tenant/workflow labels，让不同供应商 trace 可比较。
- **Eval-as-CI**：把 prompt、model、tool、retrieval 测试表示为可重复 matrix，并给出 pass/fail assertion 与 release decision。
- **Model gateway evidence**：在 Agent 继续执行前记录 route、provider/model、fallback、retry count、budget decision、rate-limit reason、final response status。
- **Inference runtime metrics**：采集 self-hosted 或 gateway 推理的 throughput、latency percentile、timeout、concurrency、batching、resource pressure。
- **Platform app boundary**：把用户聊天界面、app workflow、tool calls、knowledge sources、permissions、audit trail 分开治理。
- **Guardrail evidence**：记录 validator name、verdict、repair attempt、fail-closed decision、matched policy、owner，让安全检查可 replay。
- **Safety eval battery**：维护 prompt injection、refusal、data leakage、toxicity/harm、hallucination、safety/usability tradeoff 的版本化测试集。
- **Trace dataset loop**：把生产 trace 转成 reviewed dataset、annotation label、eval case，但不把原始私有 prompt 直接当 golden fixture。
- **Memory governance evidence**：使用 memory 作证据前记录 source、confidence、owner、conflict、update/delete action、privacy scope。
- **Local model boundary**：把 local model registry、pull/run command、model id/version、resource limits、network policy、trace fields 分开管理。
- **Experiment evidence**：把 prompt、model、tool、dataset 变更绑定到 run id、parameters、metrics、artifacts、comparison decision。
- **MCP server boundary**：执行前记录 server id、tool name、input schema、permission scope、transport/lifecycle state、result status、audit actor。
- **Graph state boundary**：多步 Agent flow 要定义 state schema、node transitions、checkpoint id、retry count、interrupt owner、stop condition。
- **Typed tool output**：tool/model 输出先过 schema validation，再进入下游状态；记录 validation error 和 retry budget。
- **RAG pipeline boundary**：把 ingestion、retrieval、ranking、reranking、citation、answer policy 作为独立证据点。
- **Browser action trace**：记录 visible context、action intent、DOM/screenshot summary、retry budget、rollback note。

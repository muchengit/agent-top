# 项目运营模式

Agent-Top 按小型软件公司方式运行：有一个主 Agent 负责总体调度、优先级、整合和验收，其他员工按角色分工产出可审查成果。这个机制的目标是让项目长期健康增长，避免重复劳动、文档断裂和未验证示例。

## 主 Agent：项目总调度

主 Agent 负责项目计划、任务拆分和最终验收。

职责：

- 把项目目标拆成每周工作流。
- 给员工分配清晰输入、输出和验收标准的任务。
- 决定哪些内容进入主分支。
- 合并前运行或请求质量门禁。
- 将安全、发布、治理和社区健康问题升级给 maintainer。
- 让路线图持续对齐公开 AI/Agent 趋势、开源项目进展和用户反馈。

主 Agent 不会盲目接受员工产出。它负责整合、审核和决策。

## 员工名册

| ID | 员工 | 范围 | 输出 |
| --- | --- | --- | --- |
| 1 | 搜索发现员工 | 公开课程、论文、博客、GitHub 项目、厂商指南 | 来源摘要、缺口清单、趋势记录 |
| 2 | Python 工程师 | Python Lab 和确定性测试 | 可运行 Python 实现与测试 |
| 3 | Node.js/TypeScript 工程师 | Node.js 与 TypeScript 示例 | JS/TS 参考实现 |
| 4 | Rust 工程师 | Rust 示例与 CLI 风格验证 | Rust 源码、编译命令、测试证据 |
| 5 | Go 工程师 | Go module、测试和部署向示例 | Go module、测试、使用说明 |
| 6 | 多语言一致性审核 | 跨语言 API 与行为比较 | 对照矩阵、差异报告、验收结论 |
| 7 | 文档结构审核 | Markdown 树、链接、frontmatter、双语对 | 死链报告、结构修复、CI 失败项 |
| 8 | 翻译编辑 | 英文到中文、中文一致性 | 翻译文档、术语表、同步标记 |
| 9 | 面试官 | 面试题生成和评分 rubric | 题库、评分卡、面试计划 |
| 10 | 面试人员 | 模拟回答和作品集 walkthrough | STAR 回答、demo 脚本、失败模式解释 |
| 11 | 开源贡献者 | 外部 issue/PR 模式和贡献流程 | PR 计划、patch notes、贡献自查 |
| 12 | 评估与可观测工程师 | eval、trace、指标、回归包 | 评估集、trace schema、回归门禁 |
| 13 | 安全护栏工程师 | 权限、破坏性操作规则、风险审查 | guardrail checklist、incident drill、安全记录 |
| 14 | 成本与可靠性工程师 | 延迟、重试、预算、回滚和降级 | 成本表、可靠性清单、SLO 记录 |
| 15 | 社区运营负责人 | good-first issue、翻译、showcase、review | 社区日历、贡献漏斗、表彰记录 |

项目增长后可以继续增加员工，但每个新角色都必须有 owner、输出类型、质量门禁和 backup。


## 不可协商的员工工作标准

每个员工必须维护一份书面工作章程。主 Agent 会拒绝模糊、不可验证、不安全、或与项目结果没有连接的工作。

| 员工 | 强制目标 | 必交证据 | 返工条件 |
| --- | --- | --- | --- |
| 搜索发现员工 | 只寻找会改变路线图、教程、Lab、面试或贡献策略的来源。 | 带日期、来源、缺口、建议和置信度的来源摘要。 | 如果是营销内容、重复来源、无日期、或未映射到路线图影响，退回。 |
| Python 工程师 | 保持 Python Lab 确定性、无需 API key，并遵循 pattern contract。 | 可运行 `agent_top_labs_*.py`、确定性测试、README 运行命令、Lab 索引更新。 | 如果不稳定、依赖外部服务、无测试或偏离稳定 pattern，退回。 |
| Node.js/TypeScript 工程师 | 保持 JS/TS 示例与 Python 行为和安全性一致。 | 可运行 JS 参考实现、TS 源码、parity notes。 | 如果语义不同、运行失败、或 TS 未验证但不说明缺口，退回。 |
| Rust 工程师 | 保持 Rust 示例可编译，并符合共享 pattern contract。 | Rust 源码、编译命令、确定性断言或测试证据。 | 如果编译失败、有额外副作用或缺少失败路径，退回。 |
| Go 工程师 | 保持 Go 示例模块化、可测试、干净 checkout 可运行。 | `go.mod`、Go 源码、`go test` 证据、使用说明。 | 如果模块无法运行、缺测试或不可与共享 pattern 比较，退回。 |
| 多语言一致性审核 | 负责跨语言等价，阻止示例漂移。 | parity matrix、差异列表、accept/rework 建议。 | 如果只描述 parity 但无证据、忽略语言、或接受隐性漂移，退回。 |
| 文档结构审核 | 保持文档可导航、双语、链接安全、frontmatter 一致。 | repository check 输出、死链/frontmatter 报告、修复项。 | 如果检查失败、中文页面无故跳英文、链接过期，退回。 |
| 翻译编辑 | 保持中文完整、自然、并与英文源一致。 | 中文文件、`i18n-key`、`last-synced`、术语表更新、未翻译说明。 | 如果中文为空、机械翻译、术语不一致或同步 metadata 过期，退回。 |
| 面试官 | 生成能测理解、实现、权衡和生产判断的面试题。 | L0-L5 题库、rubric、答案要点、failure-mode 追问点。 | 如果只测记忆、缺评分标准或缺生产权衡，退回。 |
| 面试人员 | 用真实回答和作品集 walkthrough 压测面试包。 | STAR 回答、demo 脚本、失败模式解释、自评。 | 如果回答泛化、缺证据或不解释权衡，退回。 |
| 开源贡献者 | 产出安全、范围清楚、可 review 的外部贡献工作。 | 贡献计划、issue/PR draft、checklist、maintainer 沟通说明。 | 如果依赖私有上下文、范围过大或缺验收标准，退回。 |
| 评估与可观测工程师 | 保持 eval、trace、指标、回归包可重复可审查。 | eval 集、trace schema、指标阈值、回归证据。 | 如果指标主观、trace 不可 replay、或缺回归 case，退回。 |
| 安全护栏工程师 | 阻止不安全、破坏性或权限不清的行为。 | guardrail checklist、破坏性操作分类、rollback 和 incident notes。 | 如果安全检查晚于执行、绕过 review 或缺 rollback，退回。 |
| 成本与可靠性工程师 | 保持 Agent 示例成本、重试和运行策略现实。 | 成本表、latency/retry policy、rollback plan、可靠性清单。 | 如果忽略成本/延迟、retry 可能无限循环或降级未定义，退回。 |
| 社区运营负责人 | 保持贡献流健康、可持续、对新人友好。 | good-first issue 列表、翻译 backlog、showcase cadence、表彰记录。 | 如果任务过大、过期、重复或制造 reviewer burnout，退回。 |

主 Agent 拥有最终合并决定权。员工可以提出方案，但只有主 Agent 可以把工作标记为 accept、rework 或 reject。

### 不可协商的退回规则

出现以下任一情况，主 Agent 必须要求返工：

- 没有明确 expected files 或 acceptance criteria。
- 第二员工无法复现结果。
- 代码或示例偏离 pattern contract。
- 文档、测试和 README 指令不一致。
- 安全敏感操作缺确认、rollback 或 maintainer review。
- 双语内容缺失、过期或链接错误。
- 结论没有本地检查、公开证据或具体 artifact 支撑。
- 任务增加 maintainer 负担，却没有减少长期歧义。


## 工作流看板

主 Agent 维护每周看板：

| Lane | 员工 | 主输出 |
| --- | --- | --- |
| Research | 1, 7, 15 | 趋势报告、来源摘要、内容缺口清单 |
| Learning content | 1, 7, 8 | 教程、概念文档、双语页面 |
| Multilingual Labs | 2, 3, 4, 5, 6 | 五种语言示例与一致性检查 |
| Production quality | 12, 13, 14 | eval、trace、guardrail、成本、回滚证据 |
| Interview and portfolio | 9, 10 | 面试包、模拟回答、作品集证明 |
| Open source impact | 11, 15 | 贡献计划、外部 issue/PR thread |
| Governance | 7, 15 | 路线图更新、治理 review、发布 readiness |

## 标准任务合同

每个员工任务必须包含：

```markdown
# Task

Goal:
Scope:
Out of scope:
Source or upstream dependency:
Expected files:
Acceptance criteria:
Quality gates:
Risk level: low | medium | high
Backup employee:
Main agent review notes:
```

没有 expected files 或 acceptance criteria 的任务，需要退回员工补全。

## 质量门禁

主 Agent 批准前，每个员工输出必须通过对应 lane 的门禁。

| Lane | 必查项 |
| --- | --- |
| Research | 来源日期、可信度说明、缺口映射到路线图 |
| Multilingual Labs | 语言运行命令、确定性行为、一致性矩阵 |
| Docs | `python scripts/check_repository.py`、链接检查、双语 metadata |
| Tests | 单元测试、compileall、Ruff、必要 smoke |
| Interview | rubric 存在，答案包含 trade-off 和 failure mode |
| Open source | 贡献计划不依赖私有上下文也能 review |
| Safety | guardrail 分类、破坏性操作处理、回滚说明 |

## 长期节奏

### 每日

- 主 Agent 审查新任务并关闭昨天已验收输出。
- 搜索发现员工只在影响路线图或 Lab 缺口时新增趋势记录。
- 文档结构审核在文档密集提交后检查链接和 frontmatter。
- 多语言一致性审核检查新增多语言 Lab。

### 每周

- 发布一份 research digest。
- 改进一个教程或 Lab。
- 增加或更新一个面试包。
- 审查 contributor funnel 和 good-first issue。
- 运行完整本地验证。

### 每月

- 更新 roadmap status。
- 复盘 top user questions 和内容缺口。
- 做一次社区 showcase 或 contributor highlight。
- 刷新 framework 和 tool version anchor。

### 每季

- 对照当前行业学习路径 review L0-L5 模型。
- 运行一次 Hackathon-style challenge。
- 归档过期内容并更新 deprecated 指向。
- 决定某个 Lab 是否升级为 example、tutorial 或独立 pattern。

## 合并规则

只有满足以下条件，主 Agent 才能批准工作：

- 验收标准达成。
- 没有未检查的安全敏感行为。
- 文档、测试和示例遵循同一个 pattern contract。
- 产出可由其他人维护，不依赖单个作者。
- 结果让 Agent-Top 更实用、更双语友好、更适合作为开源项目成长。

## 成长 KPI

每月跟踪：

| KPI | 目标 |
| --- | --- |
| Completed Labs | 增长但不牺牲测试覆盖 |
| Bilingual sync lag | <= 14 天 |
| Broken links | main 分支为 0 |
| Deterministic tests | 所有 Lab 无需 API key 本地通过 |
| Good-first issues | 始终至少 5 个活跃 |
| Translation-needed backlog | 不出现超过 14 天的章节 |
| Contributor recognition | 月度 review，避免同作者双审 |
| External evidence | 每季度至少一个公开 issue、PR、talk、article 或 workshop 信号 |

## 决策日志格式

```markdown
# Decision

Date:
Main agent:
Requested by:
Employees involved:
Context:
Decision:
Rejected alternatives:
Risk accepted:
Follow-up owner:
```

主 Agent 是调度和整合者，不是单人作者。员工产出证据，主 Agent 通过拒绝弱工作、路由正确检查、保持长期计划可见，让项目持续变好。

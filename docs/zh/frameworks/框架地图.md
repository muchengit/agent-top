框架地图

Agent-Top 把框架当作稳定模式的例子。持久学习目标是 pattern，框架是版本化实现。

## 阵营

| Camp | Frameworks | 为什么重要 | Best Fit | 注意 |
| --- | --- | --- | --- | --- |
| Graph orchestration | LangGraph | 明确状态、循环、checkpoint、调试 | 复杂 workflow、human review、retry | orchestration overhead |
| Multi-agent | CrewAI, AutoGen | 角色 workflow 和对话协调 | 专门化 agent、角色边界 | coordination cost |
| Lightweight | Smolagents, Agno | API 小、迭代快 | 小 Agent、学习、demo | 生产控制需额外添加 |
| SDK | OpenAI, Claude, Google ADK | 平台模型 API | 平台原生功能 | 绑定 provider |
| Type-safe | Pydantic AI | schema 和 validation ergonomics | structured output | schema discipline |
| Enterprise | Semantic Kernel | .NET/企业生态、插件 | 企业栈、治理插件 | 企业约束 |
| RAG | LlamaIndex, Haystack | 检索和文档 pipeline | 搜索密集应用 | 仍需 evals |
| Optimization | DSPy | 声明式 prompt/pipeline optimization | prompt pipeline | 需要强 eval harness |

## 框架选择问题

- 是否需要 graph state 和 checkpoints？
- 是否需要 multi-agent role separation？
- 是否需要 provider-native model APIs？
- 是否需要强 schema validation？
- 是否需要 enterprise plugin governance？
- 是否需要 RAG-specific pipelines？
- 是否需要 prompt optimization？
- 下一个季度是否还能维护？

## 框架选择决策树

引入框架代码进 Lab 前，按这个顺序判断：

1. 是否能用纯 Python loop 和显式 prompt 讲清楚？能就保持 tutorial framework-free。
2. 主要需求是否是模型调用、工具、结构化输出或 provider 功能的稳定 SDK 边界？是就用 SDK camp 做 Lab 参考。
3. 是否需要命名状态、分支、循环、人工审批、checkpoint 或可回放调试？是就用 LangGraph 风格 graph orchestration。
4. 是否需要角色拆分、专家 prompt 或多 Agent 验证？是就先对比 CrewAI 和 AutoGen 风格模式，再决定是否加编排。
5. 主要不确定性是否是检索：chunking、ranking、filtering、source freshness 或 evals？是就先用 RAG framework，但必须定义检索指标。
6. 目标是否是 prompt 或 pipeline optimization，并且已有 benchmark？是才用 DSPy 风格 optimization，且必须有 eval harness。
7. 团队是否已经绑定强类型或企业生态？是就根据 surrounding stack 选择 Pydantic AI 或 Semantic Kernel。

默认规则：先不用框架，直到 Lab 证明某个边界缺失。只有当框架能减少状态管理、测试、可观测性或维护成本时，框架才值得进入主干示例。

## 稳定边界

不管框架，都应教：

- 感知 和 context assembly。
- Tool invocation 和 validation。
- 规划 loops 和 stop conditions。
- 记忆 lifecycle。
- Retrieval boundaries。
- Observability。
- Safety guardrails。
- Rollback 和 failure modes。

## 框架权衡示例

### LangGraph vs 纯循环

系统需要以下能力时用 LangGraph：

- 持久状态。
- 带显式 checkpoint 的循环。
- 人工审批节点。
- 可回放调试。

系统需要以下特性时用纯循环：

- 最小代码量。
- 教学清晰度。
- 分支少。
- 本地测试容易。

### CrewAI/AutoGen vs 单 Agent

以下情况用多 Agent：

- 工作可清晰分解。
- 专门化角色能提升验证或隔离。
- 团队能拥有每个角色。

以下情况避免多 Agent：

- 单 Agent + 工具就够。
- 共享状态协调复杂。
- 调试已经很难。

### RAG 框架 vs 自定义检索 Lab

以下情况用 RAG 框架：

- 文档 pipeline 组件多。
- 评估需要成熟的索引支持。

以下情况用自定义检索 Lab：

- 学习目标是检索边界。
- 需要确定性本地示例。

# 模型幻觉

模型幻觉是 LLM 产生自信但无支持、错误、过时或编造内容的现象。在 Agent 系统中，幻觉更危险，因为下一步可能基于这个生成 claim 执行动作。

## 类型

| 类型 | 描述 | 例子 |
| --- | --- | --- |
| Factual hallucination | 错误事实或编造细节 | 声称存在不存在的 policy |
| Source hallucination | 编造 citation 或 evidence | 引用不存在的文档 |
| Overconfidence | 把不确定说成确定 | 说 “rollback definitely succeeded” |
| Stale knowledge | 使用过时模型知识 | 用旧 API 行为回答 |
| Tool hallucination | 误读或忽略 tool result | tool 成功却说失败 |
| Plan hallucination | 计划不可能执行的下一步 | 调用不存在 tool |

```mermaid
flowchart QR
  Q[Question] --> M[Model Claim]
  M --> R[Retrieval / Tool Evidence]
  R --> V[Verifier]
  V --> Safe[Answer with Evidence]
  V --> Refuse[Refuse / Clarify]
```

## 为什么 Agent 会放大幻觉？

普通聊天答案只会误导用户。Agent 可能先误导用户，再执行动作。

高风险场景：

- 写入带编造 citation 的文档。
- 基于虚构 policy 调用工具。
- 把 stale memory 当成当前事实。
- 把 model confidence 当成授权。
- 总结 tool output 时加入额外编造细节。

## 缓解方式

- 对私有、当前或事实性 claim 使用 retrieval。
- Evidence-heavy answer 必须提供 citation。
- 不可逆动作前先验证 generated claims。
- Model confidence 和 tool success 要分开。
- Evidence 缺失时提供 refusal path。
- 记录 prompt、retrieved context、tool output、model claim 和 final answer。
- 为幻觉事实、缺失 citation、过时事实、无支持建议建立 evals。

## Review 时要问什么？

- 哪些 claim 是事实性且需要 evidence？
- 系统能不能 refuse 而不是猜测？
- Citations 是否对照真实 retrieved sources 检查？
- Verifier 是否在动作前阻断 unsupported claims？
- Stale memory 是否和 verified facts 分开处理？

## 生产备注

- Postmortem 中把 hallucination 作为失败类别记录。
- 每个 hallucination incident 增加 regression prompt。
- 优先 refuse 或 clarify，而不是自信猜测。
- 最终答案中暴露 evidence freshness。

## 深入：幻觉评估

幻觉评估应衡量 unsupported claims，而不是判断回答是否流畅。有用类别包括 factuality、citation correctness、abstention、overstatement、tool misuse 和 stale knowledge。

最小 eval set 应包含：有明确 evidence 的问题、evidence 缺失的问题、stale sources、contradictory sources、tool-result cases 和 safety-sensitive cases。评分时检查 answer 是否引用了正确 source、是否避免 unsupported claims、evidence 缺失时是否 refuse、tool evidence 改变时是否改变答案，以及是否阻断了 unsafe action。

## 幻觉和动作

最危险的不是聊天幻觉，而是触发动作的幻觉：因为 model 相信工具存在而调用工具、用 fabricated details 更新 ticket、写入 invented citations，或基于 invented policy 批准 risky action。这类问题需要 action gates：schema validation、permission checks、evidence verification、不可逆步骤 human approval，以及 regression evals。

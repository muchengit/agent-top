# Maintainer Rotation

## Purpose

Prevent burnout, keep bus factor low, and keep review standards consistent.

## Rules

- Each active module should have at least two maintainers or backups.
- Module leads rotate quarterly.
- Same person should not author and review the same module in the same month.
- Architecture, safety, and production topics require Maintainer review.
- Ordinary Labs require Reviewer review.

## Rotation Inputs

- Recent merged contributions.
- Review capacity.
- Translation sync load.
- CI and release readiness.
- Burnout signals.

## Quarterly Handoff

1. Review active module ownership.
2. Identify backup maintainer for each module.
3. Update roadmap status.
4. Flag stale or abandoned modules.
5. Publish a short handoff note in Discussions or Issues.

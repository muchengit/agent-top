# Agent Case Study Writing Guide

A case study should teach a pattern through a realistic scenario.

## Good Case Study Shape

1. Start with the user task, not the framework.
2. Show the smallest viable architecture.
3. Explain one or two hard decisions.
4. Include failure modes and evaluation evidence.
5. End with a reusable lesson.

## Required Evidence

Each case should link to at least one:

- Lab.
- Example exercise.
- Template.
- Checklist.
- Trace or eval artifact.

## What To Avoid

- Do not copy framework READMEs.
- Do not use real private data.
- Do not present model output as verified fact.
- Do not hide rollback or safety decisions.
- Do not add a pattern without a failure case.

## Review Questions

- Could a reviewer reproduce the decision logic?
- Does the case explain when not to use the pattern?
- Is there a deterministic or repeatable check?
- Are tool risks and permissions explicit?
- Does the case contribute a portable Agent skill?

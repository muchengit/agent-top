# Agent 案例研究写作指南

案例研究应该通过真实场景教一个模式。

## 好的案例结构

1. 从用户任务开始，不从框架开始。
2. 展示最小可行架构。
3. 解释一到两个硬决策。
4. 包含失败模式和评估证据。
5. 以一个可复用教训结束。

## 必要证据

每个案例至少链接一个：

- Lab。
- Example exercise。
- Template。
- Checklist。
- Trace 或 eval artifact。

## 要避免

- 不要复制框架 README。
- 不要使用真实私有数据。
- 不要把模型输出当成已验证事实。
- 不要隐藏 rollback 或安全决策。
- 不要在没有失败案例时新增 pattern。

## Review 问题

- Reviewer 能否复现决策逻辑？
- 案例是否说明了什么时候不要用这个 pattern？
- 是否有确定性或可重复检查？
- Tool risk 和权限是否明确？
- 案例是否贡献了一个可迁移 Agent skill？
